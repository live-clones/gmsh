The Gmsh web app: Gmsh compiled to WebAssembly with Emscripten (experimental)

Build (needs emsdk, by default in ~/src/emsdk, and the GetDP sources, by
default in ../getdp next to the Gmsh sources):

  ./build.sh

The first build downloads and builds OpenCASCADE, and PETSc with SuiteSparse
and f2c BLAS/LAPACK for GetDP, in ./build/deps (about half an hour); then Gmsh
and GetDP. "./build.sh --no-occ --no-getdp" builds Gmsh alone.

Serve the Gmsh source tree over HTTP and open the pages, e.g.

  python3 -m http.server 8000 --bind 127.0.0.1 --directory ~/src/gmsh

  http://localhost:8000/contrib/webapp/viewer.html
  http://localhost:8000/contrib/webapp/onelab.html

viewer.html shows a model and meshes it; onelab.html is the ONELAB app: it
opens a model (a .pro file with the .geo of the same name and the files they
include, given as files, a folder, a zip archive, or ?zip=<url>), shows its
parameters, and runs Gmsh and GetDP, in the page.

The build writes the library, libgmsh.mjs and libgmsh.wasm, in ./build, next
to a copy of the JavaScript API, api/gmsh.mjs (generated by api/gen.py):

  import createGmsh from './build/gmsh.mjs';
  const gmsh = await createGmsh();

api_test.mjs shows its use and checks it:

  node api_test.mjs

The pages draw the scene with the functions of webView.cpp; webOnelab.cpp
links GetDP in and runs the ONELAB loop.
